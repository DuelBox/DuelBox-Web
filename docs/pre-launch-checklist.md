# Pre-launch checklist

Launch day is the wrong time to discover the rollback procedure was never tested (#234). This
is the one checklist run before the site is made public: performance, accessibility, legal,
SEO, analytics, and rollback readiness, each item pointing at the guard, doc or route that
already covers it so this is a sign-off sheet rather than a second source of truth.

**Authoring this checklist is one job; running it is another.** Most items below are verified
by something automated that runs in CI already — those are marked *(auto)* and the checklist's
job is to confirm the guard is green on the release candidate. The rest are *(human)*: a
person has to look, and launch is the deadline for having looked. This document is the sheet;
**the sign-off is a human step and is not performed here.** The section at the end is what a
person fills in.

## How to use it

Run against the exact commit proposed for launch. For every item, record PASS / FAIL / N-A
with a link to the evidence — the green CI job, the doc, the route, or the note. A FAIL blocks
launch; an N-A needs a one-line reason. Do not tick an item you have not checked: this project
has shipped three guards that asserted something nothing ran, and a checklist ticked from
memory is the fourth.

## Performance

- [ ] *(auto)* **Size budget green.** `pnpm build` runs `check-size.mjs`; shell, on-demand and
      per-game chunk all under `size-budget.json`. A launch build over budget does not ship.
- [ ] *(auto)* **Zero-cost guard green.** `check-zero-cost.mjs` — no server runtime, no dynamic
      routes, no gameplay touching the network, session under 700 kB.
- [ ] *(human)* **Budgets defined and understood.** `docs/performance-budgets.md` records the
      LCP/INP/CLS targets on a mid-range Android over 4G and the 60fps / 30fps-floor gameplay
      targets. Confirm they are still the intended numbers.
- [ ] *(auto)* **Lab Web Vitals under the thresholds.** `lighthouse.yml` runs `@lhci/cli` on
      every pull request against the built export, mobile-throttled, and fails below
      `lighthouserc.json` (#184). Field vitals are not collected — no analytics, by design — so
      a launch has the lab number and a human with a phone, not a dashboard.
- [ ] *(auto)* **Session bytes under budget.** `check-size.mjs` holds a first session, a
      browsing session and the catalogue on screen to `size-budget.json` (#2446, #2419).

## Accessibility

- [ ] *(auto)* **axe scan clean.** `e2e/axe.spec.ts` on every shell page (Chromium).
- [ ] *(auto)* **Screen-reader landmarks and focus.** `e2e/screen-reader.spec.ts` — skip link
      moves focus, `<main>` reachable, live regions present, on both Chromium and WebKit.
- [ ] *(auto)* **Touch targets ≥ the token.** `e2e/touch-targets.spec.ts` at 320px.
- [ ] *(auto)* **Playable in greyscale.** The `greyscale` harness — colour is never the only
      signal (CLAUDE.md rule 7).
- [ ] *(auto)* **Reduced motion respected.** `Canvas2DRenderer.setReducedMotion` and its test.
- [ ] *(human)* **Keyboard-only pass of a full journey.** Catalogue → play → result → rematch
      with no pointer. This project reopened an issue for closing it on an unchecked claim
      (HANDOFF.md); do the pass, do not assert it.
- [ ] *(human)* **A real screen reader on one game and the catalogue.** VoiceOver or NVDA, once.

## Legal

- [ ] *(auto)* **Every game name cleared.** `check-game-names.mjs` — every catalogue game has a
      recorded name decision with a reason (`data/name-clearance.json`), and no coined name
      above the pending ceiling.
- [ ] *(auto)* **Every asset licensed.** `check-asset-licenses.mjs` — rule 3.
- [ ] *(human)* **Privacy policy published and linked.** `/privacy/`, in the footer (#212).
- [ ] *(human)* **Terms published and linked.** `/terms/`, in the footer.
- [ ] *(human)* **Third-party attribution published.** `/attribution/`, generated by
      `scripts/emit-attribution.mjs`, linked in the footer (#215).
- [ ] *(human)* **DMCA / abuse contact live.** `/dmca/` route and `docs/abuse-response.md`
      procedure (#216) — **and the placeholder `abuse@duelbox.example` replaced with a real
      monitored address.** This is an owner-supplied detail; the route ships with a flagged
      placeholder and must not launch with it.
- [ ] *(human)* **IP clearance review complete.** The full-catalogue written review (#210), of
      which `data/name-clearance.json` is the per-name record.
- [ ] *(human)* **Child-audience decision made and honoured.** The general-audience-vs-child
      -directed decision (#214), with analytics and any ads configured to match it. Blocks the
      analytics section below.
- [ ] *(human)* **Originality review filed.** The screen-by-screen review that answers a
      complaint if one arrives (#2339).

## SEO

- [ ] *(auto)* **Sitemap and robots correct.** `app/sitemap.ts` / `app/robots.ts` and their
      tests; canonical URLs resolve against the deploy origin (set via `NEXT_PUBLIC_SITE_URL`
      in `deploy.yml`).
- [ ] *(auto)* **CSP permits every origin the pages load.** `csp-origins.test.ts`.
- [ ] *(auto)* **Share images present.** `check-share-images.mjs` — one per game plus the site.
- [ ] *(human)* **Metadata spot-check.** Title, description and OG card on the landing page, one
      game page, and one category hub. Base path baked in for a project-page deploy.
- [ ] *(human)* **Canonical origin is the launch origin.** If moving off GitHub Pages to restore
      response headers (#2481), the canonical URLs and sitemap must name the new origin.

## Analytics

- [ ] *(human)* **Analytics matches the child-audience decision (#214).** If child-directed: no
      behavioural analytics, minimal data. If general audience with age gating: the gate exists
      and the analytics config matches what was written down.
- [ ] *(human)* **Disclosed in the privacy policy.** Whatever is collected — analytics, local
      storage — is named in `/privacy/` before it is collected.
- [ ] *(auto)* **No secret in the bundle, no non-public env var.** `check-bundle-secrets.mjs` —
      an analytics key added carelessly is exactly what it catches.
- [ ] *(human)* **Local storage inventory.** Settings, last-mode and head-to-head are the only
      stores; each fails safe when storage is absent. Confirm nothing new was added undisclosed.

## Rollback readiness

The point of this whole document: the rollback must be *tested before* launch, not discovered
during it.

- [ ] *(human)* **Rollback rehearsed.** Deploy is a static export via `deploy.yml` (GitHub
      Pages today). Confirm the exact steps to revert to the previous good build, and **run
      them once** against a staging or the live Pages deployment to a prior commit, then
      forward again. Record how long it took.
- [ ] *(human)* **Previous good build identified.** The commit SHA to roll back *to* is known
      and its artefact is reproducible (`pnpm build` from that SHA is deterministic — the whole
      argument of `docs/adr/0001-static-first-hosting.md`).
- [ ] *(human)* **Deploy concurrency and half-deploy safety confirmed.** `deploy.yml` uses
      `concurrency: pages, cancel-in-progress: false` so a deploy is never left half-done;
      confirm that is still the case on the launch workflow.
- [ ] *(human)* **`.nojekyll` and hidden files ship.** `deploy.yml` touches `.nojekyll` and sets
      `include-hidden-files: true`; both were once silently dropped (#2513). Confirm the launch
      artefact serves `/_next/…` and `/.well-known/security.txt`.
- [ ] *(human)* **Security header story understood.** If still on GitHub Pages, the generated
      `_headers` / `vercel.json` / CSP are **not served** (#2481) — a known, accepted downgrade
      that the iframe threat model (#2367) depends on being fixed. Either move to a host that
      serves them before launch, or accept it in writing with an owner and a date.

deliberately not pre-ticked.
