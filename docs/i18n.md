# Internationalisation

The framework behind #219 (lazy locale bundles), #223 (the pseudo-locale that makes text expansion
visible) and the `dir` half of #222, and the ground #220 (extraction), #221 (translation) and #224
(fonts) build on. Everything lives in `apps/web/src/lib/i18n/`; this page is the map, the budget
argument, and the list of things that are deliberately not translated.

The two sentences to take away: **a locale is a choice, never a detection**, and **only the chosen
locale is ever downloaded**. Both are properties of the build that a test or a build script fails
on, not promises in a README, and the last section says which guard holds which.

## The design, and why the key is the English string

`t(messages, 'Mute sound')` looks up the English sentence itself. A catalogue is a flat record from
English to the translation — `{ 'Mute sound': 'Silenciar' }` — and there is no `sound.mute` id and
no table mapping ids to English anywhere.

That is a budget decision, and the number behind it is in `size-budget.json`: on the day this
landed the shell had **856 bytes** of headroom under its budget, and every byte of the shell is paid
by every visitor on every route. A dotted-key design ships every string twice — once in an English
table and once, as the id, at the call site — which over the site's copy is a few kilobytes gzipped
that no visitor asked for. English-as-key moves a literal that was already in the chunk into a call
and costs the wrapper only. The pilot in a sibling worktree was built the other way; its reasoning
about laziness, hydration and the guards was kept, its key design was not.

Three other things fall out of the choice:

- **Data strings translate through the same lookup.** A game's `rule` from
  `catalogue.generated.ts` or a category name is `t(messages, entry.rule)`; nothing is extracted by
  hand. The extractor cannot see a variable, so such sources are registered in `sources.ts`,
  which #220 filled: twenty entries, each computed by the function the render site calls.
- **The lint rule is mechanical.** No bare text in JSX; the seven user-facing attributes go through
  `t()`. There is no id to invent, so there is nothing for a reviewer to argue about.
- **The cost every English-keyed system pays:** two identical English sentences that mean different
  things share one translation. The fix is to make the English differ.

The pieces, each documented in its own header:

| Module | What it is |
|---|---|
| `locales.ts` | The registry `LOCALES` (code → `{ name, dir }`), `DEFAULT_LOCALE`, `isLocale`, `resolveLocale`, `localeFromSearch`, `applyLocale` (stamps `lang` and `dir` on `<html>`). No message text. |
| `messages.ts` | `Catalogue`, `t(catalogue, id, values?)` and `plural(catalogue, locale, count, forms)`. Pure. `Intl.PluralRules` is the only `Intl` in the framework. |
| `load.ts` | `IMPORTERS`, one static-specifier `import()` per non-default locale, and `loadCatalogue`, which imports nothing for English and falls back to English when a chunk cannot be fetched. |
| `provider.tsx` | `LocaleProvider`, mounted once in `app/layout.tsx`. Subscribes to the settings, loads the catalogue in an effect, applies `lang`/`dir`, honours `?lang=`, drops a chunk that lands after the locale moved on. |
| `use-messages.ts` | `useMessages()` and `useLocale()` from the context. |
| `T.tsx` | `<T id="…" values={{…}} />` for server components and for copy with inline markup. |
| `pseudo.ts` | The `en-XA` and `ar-XB` transforms. Deterministic; placeholders survive. |
| `sources.ts` | Where dynamic-data sources are registered for the extractor: the game rules and controls, category names in both spellings, round lengths, landing and hub copy, the settings import names and refusals, the match-options labels and refusal reasons, the offline bar, the bot tiers, the health words, the SDK's error fallback, the manifest option labels. |
| `extract.ts` + `extract.test.ts` | The extractor and the generator of `messages.en.generated.json` and the pseudo catalogues. |
| `catalogues/*.generated.ts` | One module per generated locale, `{ locale, messages }`, committed. |

### The first render is English, always

The site is a static export. The server rendered English into the HTML, so the first client render
has to produce English too or React throws the markup away on a hydration mismatch. The provider
therefore starts at the default locale with an empty catalogue — every lookup falls through to the
English id, byte for byte what the server wrote — and the stored choice and its chunk arrive in
effects a frame later. A visitor on English never sees a flash because their catalogue *is* the
empty one. The inline script in the layout stamps `lang` and `dir` before paint for the same reason
the theme script does: a right-to-left choice that waited for hydration would paint the shell the
wrong way round and flip it. The provider, for its part, stamps nothing until `useSettings` reports
that storage has been read — its first render holds the default locale, and applying *that* would
put `en`/`ltr` back over the script's stamp for a frame. The first draft did exactly that, and it
was measured rather than noticed: `ar-XB/rtl → en/ltr → ar-XB/rtl` within 40 ms of `load` on
every route on both engines, WebKit holding the wrong values for 10–44 ms and painting a frame the
wrong way round on two of the four routes probed, with the end state correct and every test green. The reload test in
`e2e/i18n.spec.ts` now watches every change to the two attributes after `DOMContentLoaded`.

### `<T>` in a server component costs no script

Most of this site's copy is in server components — the landing page, the catalogue, every game's
page — and those cannot call `t()`, which needs the context. `<T id="…" />` is how they translate:
the server component passes the English as a prop, React serialises the element into the route
payload and renders its English into the HTML, and on the client the component looks the id up
like any other. **Checked on the built export, not assumed**: the settings page's lede goes through
`<T>`, and its English appears in `settings/index.html`, in `settings/index.txt`, and in the two
locale chunks (as the key, which is inherent to English-as-key — a locale chunk carries the English
it translates) — and in no shell or route chunk under `_next/static/chunks`.

Where *not* to put one: the root layout. Every element in `layout.tsx` is serialised into all 108
play-route payloads a catalogue browse prefetches, so a `<T>` there is paid 108 times on the
`speculatedBytes` line. The skip link's text is still a literal for exactly that reason.

## What a call site looks like

```tsx
// A client component.
const messages = useMessages();
<button aria-label={muted ? t(messages, 'Unmute sound') : t(messages, 'Mute sound')} />

// With values. A missing value renders the placeholder as written, on purpose.
t(messages, 'Round {n} of {total}', { n: 2, total: 5 })

// A counted phrase. English supplies `one` and `other`; a locale with more categories
// supplies them in its catalogue as `'{count} games#few'`, and the fallback chain is
// suffixed form → translated `other` → English.
plural(messages, useLocale(), count, { one: '{count} game', other: '{count} games' })

// A server component, or copy with markup in it. Values may be React nodes.
<T id="Press {key} to pause" values={{ key: <kbd>Esc</kbd> }} />
```

The extractor reads these by shape (`extract.ts` lists the exact shapes), so the id must be a
string literal or a conditional between literals, and it must be a `t`, `plural` or `T` imported
from the i18n modules — `lib/format.ts` has a `plural` of its own that is not one. Write real
characters, not HTML entities, in a `<T id>`.

## Adding a locale: the three edits that must agree

1. **The registry.** Add the code to `LOCALES` in `locales.ts` with its name in its own language and
   its `dir`. One code per line, followed by `{` — `check-size.mjs` reads the table with a regular
   expression.
2. **The catalogue.** A pseudo-locale gets a transform in `pseudo.ts` and an entry in `PSEUDO` in
   `extract.ts`, and `pnpm i18n:extract` writes it. A reviewed translation (#221) is a hand-written
   `catalogues/<code>.generated.ts`-shaped module — `{ locale, messages }`, `locale` first — and
   the completeness test in `i18n.test.ts` is relaxed to a subset for it, since a translation is
   allowed to be partial and a pseudo-locale is not.
3. **The importer.** One line in `IMPORTERS` in `load.ts`, a static specifier inside `import()`.

And a fourth that is not a fourth place for the *strings*: the inline script in `app/layout.tsx`
carries a copy of the non-default codes and their directions in `D`, because it runs before
anything can import the registry. `i18n.test.ts` reads it back and fails if it disagrees with the
registry in either direction.

Miss any one of these and `i18n.test.ts` fails before the build does; miss the importer and
`check-size.mjs` fails the build too, with `<code> is in the locale registry and has 0 chunk(s)`.

## The extractor and the generated files

`pnpm i18n:extract` runs `extract.test.ts` with `DUELBOX_EMIT_LOCALES=1`. The same test, without the
variable, is what CI runs: it renders the same bytes and asserts that the committed files equal
them, so a string converted to `t()` without the extractor being re-run fails with the command that
fixes it. Three files are generated and committed, like `data/catalogue.generated.ts`:

- `messages.en.generated.json` — the sorted, de-duplicated msgids. This is what a translator is
  handed for #221 and what every catalogue's keys are held against.
- `catalogues/en-XA.generated.ts` — every msgid accented, padded by 35% and wrapped in `⟦ ⟧`.
- `catalogues/ar-XB.generated.ts` — every msgid with each word wrapped in a right-to-left override.

Both pseudo-locales are complete by construction, which is their whole point: **a string in plain
English on a pseudo-localised screen is a literal the extractor never saw.** That is how #220 finds
what it has missed, and it is why `i18n.test.ts` refuses a pseudo-locale with a gap and a
catalogue with a key the site never renders.

The two are not translations and must never be presented as one. Shipping a machine-translated
locale instead would have been the tempting shortcut and would have been dishonest: #221's
acceptance criterion is review by somebody who speaks the language, and a locale nobody has read
reads as broken to the people it claims to serve. A pseudo-locale cannot be mistaken for a launch
locale by anyone.

Why `ar-XB` mirrors per word rather than per string: one override across a whole sentence reverses
the order of the words as well, so a `{count}` in the middle of a line swaps sides with the noun it
belongs to and a placeholder value ends up looking like an interpolation bug rather than a property
of the locale. Per word, the failures that remain are all layout failures, which is what #222 is
looking for. Its name in the language menu is plain English on purpose: the name's job is to be
found again by somebody who has just watched the whole site flip and wants the way back.

## The lint rule

`scripts/eslint-rules/no-untranslated-text.mjs` reports bare text in JSX containing a letter, and a
string or template literal in `aria-label`, `aria-description`, `aria-roledescription`,
`aria-valuetext`, `title`, `placeholder` or `alt`. Nothing inside `<noscript>` is reported. What it
cannot see is a string that reaches JSX through a variable or a constant — `{FRAMED_NOTICE_TEXT}` is
an expression to it — so it is a ratchet on the *shape* of a file's JSX, not a proof that the file
is translated; #220's pass closes that gap by reading.

`eslint.config.js` applies it as an error to the glob `apps/web/src/**/*.tsx`. Until #220 landed it
was a ratchet, `I18N_CLEAN`, an explicit list a file joined in the commit that converted it; #220
converted every file and the list became the glob, at which point the ratchet became the rule. What
stays exempt is the subtree of `<noscript>`, which the rule skips itself, and the literals carrying
an `eslint-disable-next-line duelbox/no-untranslated-text -- <reason>` comment — every one of them
is in the list below, and a disable without a reason beside it is a review finding.
`lint-rule.test.ts` runs the rule through ESLint's `Linter` on fixtures so that it is seen failing on
every push, since the files it is applied to are all clean. What the rule cannot see — a string
reaching JSX through a variable — is what `e2e/pseudo-sweep.spec.ts` walks the pseudo-locale for.

## What the bytes cost, and the budgets

All three numbers were measured on the built export with `scripts/check-size.mjs`, against the
baseline of `origin/main` at `de870ba` built on the same machine (`size-budget.json` →
`_rederived_2026_09_12_i18n` carries the same figures beside the budgets they set).

- **Shell.** 132,374 B against 131,240 B before: **+1,134 B** for the provider, the
  context, `<T>`, `t()`, the registry, the loader's two `import()` sites and the language control
  with its note. The budget is re-derived to measured plus the same 856 B of headroom main had, as
  the brief for this work required, rather than rounded up to hide a feature in.
- **On demand.** 61,067 B against 61,065 B: unmoved within a couple of bytes, because
  nothing here touches the play route.
- **Locale.** A new bucket, `localeBytes`, the *largest* catalogue chunk — a visitor has one
  language at a time, so a sum would be the wrong number. Today `en-XA` is 929 B and
  `ar-XB` 674 B, with six strings in each; a real translation of the whole string set
  will be far larger, since a chunk carries the English keys as well as the translation. #220
  re-derived it from the full extraction: `en-XA` is 67,125 B for 884 strings, `ar-XB` 54,140 B, and
  `localeBytes` is 83,968 B, about a quarter over the larger (`_rederived_2026_09_12_extraction`). `check-size.mjs` finds a locale chunk by
  the `locale:"…",messages:` marker its module opens with, prints one line per locale, takes it
  out of the on-demand total, and fails the build on a chunk naming two locales or an unregistered
  one, a registered locale with no chunk or two, a locale chunk folded into the shell, and — a floor
  — an export with no locale chunk at all while the registry has non-default locales.
- **Speculated.** 505,829 B against 494,982 B: **+10,847 B**, which is the number that
  moved most and the one this section exists to explain. Every route payload carries the whole root
  layout, and two things were added to it: the provider's client reference (about 34 gzipped bytes
  a payload, measured by diffing one payload) and the two lines of the before-paint script that
  stamp `lang` and `dir`. The first draft of those lines — two arrays and two `setAttribute` calls —
  measured 74 B a payload; the shape that shipped, one lookup object and the reflected `lang`/`dir`
  properties, measured 67 B. Multiplied by 108 that is the whole of the delta. The
  budget is raised to 522,240 B on the arithmetic `_raised_2026_09_08_speculated_headroom`
  sets out: about one payload of headroom over the *worst* CI reading, which has been up to 4.3 KB
  above a local build of the same commit.

## What is deliberately not translated

- **Game names.** `scripts/check-game-names.mjs` holds every name against the reference app's
  (rule 1), and a translated name is a second name nobody has cleared. Names stay as the catalogue
  spells them in every locale.
- **`metadata` exports.** Titles, descriptions and share cards are read by crawlers and link
  unfurlers, which render no client component and follow no `?lang=`. They stay English, and
  `metadata-claims.test.ts` goes on holding them.
- **`<noscript>` blocks.** A scripting-off visitor cannot switch locale and the catalogue never
  loads for them; `t()` would return the English id anyway. The lint rule exempts the subtree.
- **The language menu's option names.** Each language is named in itself, because somebody looking
  for their own cannot read the name of it in a language they do not have.
- **The framed notice.** It is text a framed page shows before anything hydrates; translating it
  would mean a `<T>` in the root layout, which the budget section above rules out.
- **Landmark names.** `aria-label="Main"` and `"DuelBox home"` in the header, `"Footer"` and
  `"Game categories"` in the footer, and `"Breadcrumb"` on a game page and a hub page. An attribute
  cannot hold an element, so `<T>` cannot reach it, and `t()` needs a client boundary — which for
  the four in the root layout is paid in all 108 play payloads. Each carries a disable comment with
  that reason, and `e2e/pseudo-allowlist.ts` names all five. A follow-up that wants them has one
  small client component for the crumb nav and a measured argument for the layout.
- **`play/[slug]/loading.tsx`.** Its two lines, "Loading the game" and "Loading…". The only way to
  reach the catalogue from a server component is to import `<T>`, and `loading-states.test.ts`
  holds that file to importing nothing, because an import is what makes Next emit a segment chunk
  the file already paid to shrink. The lines are short, seen by almost nobody (#2539 could not make
  the fallback paint), and repeated a moment later in the player's language by the page itself.
- **Key caps.** `W A S D`, `Space`, `↑ ← ↓ →`, `Enter` in `SEAT_KEYS`, `Esc` in the how-to-play
  prose, and `keyLabel()`'s output in the key boxes: what is printed on the key, not a word.
- **The seat characters.** `Pip` and `Bo` are names, and a chosen player name replaces them; they
  are values inside translated sentences, never copy.
- **Filenames, paths, addresses and identifiers.** `duelbox-player-data.json`, the storage-key
  prefix `duelbox:` that the privacy page quotes, `src/styles/fonts/OFL.txt`, the email address on
  the DMCA page, and the package names, licence identifiers and author names on the attribution
  page. Each is the same string in every language; a msgid a translator must leave alone is worse
  than none.
- **Values that are not words.** The volume slider's `{percent}%`, the countdown digits, a
  share-card filename: a locale that writes a percentage differently wants `Intl.NumberFormat`, not
  a catalogue entry.
- **The URL.** `?lang=` is read and never written back, and there is no `/de/` route: a static
  export with a canonical URL per page would gain a second URL under every one of them for a
  crawler to find. If a routed locale is ever wanted it is a #220 decision, not a side effect here.

## `?lang=`

`/settings/?lang=en-XA` — or any route — asks for a locale. The provider reads it once on mount,
validates it against the registry, stores it like a choice made in the control, and never writes it
back to the address. An unknown code is ignored rather than applied, so a link from a build that
shipped a language this one does not have cannot silently drop the player's own choice. The query
stays on the URL as it arrived; it is a request, and the stored value is the answer.

## Offline

Read out of `apps/web/public/sw.js` and `scripts/emit-service-worker.mjs`, not assumed. The
precache list is built from the shell documents' `src` and `href` references and what their
stylesheets pull; a locale chunk arrives by `import()` and no document references it, so **it is not
precached** — precaching every locale for everybody would charge every visitor for languages they
did not ask for, and was declined. It **is** kept by the worker's runtime path: `respondToAsset`
saves every same-origin `basic` response it answers from the network, so a locale chosen on one
visit is answered from the device on the next, and the site in that locale opens with no
connection from the second load onward. What does not work is the *first* switch to a locale this
device has never fetched while it is disconnected: the import rejects, `loadCatalogue` resolves to
the empty catalogue, and the player sees English rather than a broken page.

## Privacy

Nothing reads `navigator.language`, and `docs/privacy-policy.md` states that as a checked row. A
language is a strong enough hint about a person that reading it silently would be a different
promise from the one that page makes. The locale is a field of the settings blob rather than a
store of its own, so it travels in a player's export and erase with the rest of the settings and
adds no key to `PLAYER_DATA_KEYS` and nothing to the privacy page's list.

## How the follow-up issues plug in

- **#220, extraction.** Landed; the section below says what happened and what it could not reach.
- **#221, translation.** Hand `messages.en.generated.json` to a reviewer; a catalogue comes back in
  the same module shape; one registry line and one importer line; the completeness test relaxed to
  a subset for that locale.
- **#222, right-to-left.** `dir` is already stamped, before paint and after; `ar-XB` mirrors the
  whole shell through the browser's own bidi layout. What remains is what does not mirror well:
  physical paddings and margins to logical properties, seat geometry, anything positioned by `left`.
- **#223, expansion.** `en-XA` pads every string by 35% and brackets it. Walk the site in it and
  file what overflows.
- **#224, fonts.** The three self-hosted faces cover Latin and Latin-ext. A real locale in another
  script needs its own subset and a `unicode-range` gate like the existing `-latin-ext` faces, so a
  page that renders none of that script fetches none of it.

## #220: the extraction

Five territories converted in parallel — the settings panel and key boxes, the play route's overlay,
HUD and track, the shell's own furniture (lobby, loading line, recovery screen, offline bar, error
boundary), the landing page, catalogue, hubs, header and footer, and the six prose pages — each
from the framework commit, each with its own report, and were merged once. Every user-facing
string in every `.tsx` under `apps/web/src` now goes through `t()` or `<T>`, or is registered
in `sources.ts` and looked up by the id the data carries; `messages.en.generated.json` holds
**884 msgids**. The rules the territories converged on, and that a new string should follow:

- One sentence is one id with placeholders, never a join of translated fragments — a locale must
  be able to move the value. Two sentences that differ only by a word are two ids when a language
  would inflect around that word ("Turn the device upright…" / "…sideways…").
- Case belongs to the position in the sentence. The bot tiers are registered capitalised for the
  radios and lower-case for the HUD; the category names capitalised for the chips and lower-case
  for "More board games". Nothing lower-cases a translated string at a render site.
- A name is a value: player names, seat characters and game names travel through `values`, and
  a rendered player name is wrapped in `<bdi>` so a right-to-left name inside a left-to-right
  sentence keeps its own direction.
- A pure module that builds a sentence — `match-announcement.ts`, `handoff.ts`, `gamepad-notice.ts`,
  `seats.ts` — takes the catalogue as a parameter, so the unit suites pass `{}` and get English.
- A data string is registered by the function the render site calls, over the data the render site
  selects, so the orphan guard genuinely holds the list against the screen.

What it did not reach, and the seam a follow-up would add: **the canvas.** Thirty-two game
packages draw English through the engine renderer's `text()` — "Roll" in Ludo, "Bonus at 63" in Yazy,
"Lay out your fleet" in Sea Battle, the score words on a dozen boards — and a game is handed a
`GameContext` (`packages/game-sdk/src/contract.ts`) with a manifest, an rng, a presentation, the
seats and a difficulty lookup, and no catalogue. The extractor does not read `packages/` and the
sweep does not read pixels, so on a pseudo-localised play screen the board is the one thing still
in plain English. The follow-up is a `messages: Catalogue` field on `GameContext` — supplied by
`GameHost`, which already reads the catalogue through a ref for exactly this kind of callback —
with the games' literals going through the same `t()`, the extractor's walk widened to
`packages/games/*/src`, and a size argument for the on-demand line, since a game chunk would carry
its `t()` calls. That is a change to the game contract and belongs to its own issue, not to this one.

## The guards, and what each was watched failing on

Every guard below was seen red on purpose before it was believed, which is the habit CLAUDE.md asks
for; the pull request lists the exact failure text for each.

| Guard | Where | Fails when |
|---|---|---|
| The lazy guard | `i18n.test.ts` | any file but `load.ts` names a catalogue path, or `load.ts` names one outside `import()` |
| Registry ↔ files ↔ importers ↔ modules | `i18n.test.ts` | the three edits above disagree, or an importer resolves to the wrong locale's module |
| Default imports nothing; failed import falls back | `i18n.test.ts` | English fetches a chunk, or a rejected import rejects the page |
| Orphans and completeness | `i18n.test.ts` | a catalogue key the site never renders, or a msgid a pseudo-locale lacks |
| Head-script table | `i18n.test.ts` | the inline script's codes or directions disagree with the registry |
| Stale generated files | `extract.test.ts` | the committed msgids or catalogues are not what the extractor would write |
| The lint rule can fail | `lint-rule.test.ts` | a bare literal, an attribute literal or a template literal is not reported, or `<noscript>` is |
| Locale bucket | `scripts/check-size.mjs` | a locale chunk is folded into the shell, doubled, missing, unregistered, or absent altogether |
| The pseudo sweep | `e2e/pseudo-sweep.spec.ts` | any text node or user-facing attribute under `header`, `main` or `footer` on twelve routes, the lobby or the pause menu carries ASCII letters that `e2e/pseudo-allowlist.ts` does not name with a reason — a literal the extractor never saw, or a value handed to a sentence untranslated |
| The wiring | `e2e/i18n.spec.ts` | `?lang=` does not reach the header, the heading and `<html>`; switching navigates; a locale other than the chosen one downloads; `dir` is not `rtl`; `lang`/`dir` are not on `<html>` by `DOMContentLoaded` after a reload |
